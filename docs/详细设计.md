## 2. 数据模型设计

### 2.1 Pydantic 模型

```python
# models/schemas.py
from pydantic import BaseModel, Field
from datetime import datetime
from typing import List, Optional, Literal

class UserProfile(BaseModel):
    user_id: str
    name: Optional[str] = None
    preferences: dict = Field(default_factory=dict)
    updated_at: datetime

class CharacterProfile(BaseModel):
    character_id: str
    name: str
    description: str
    personality: str
    speaking_style: str
    background: str
    relationship: str
    tags: List[str] = []
    created_at: datetime

class Message(BaseModel):
    role: Literal["user", "assistant", "system"]
    content: str
    timestamp: datetime
    tokens: int = 0

class SessionMeta(BaseModel):
    session_id: str
    user_id: str
    character_id: str
    started_at: datetime
    ended_at: Optional[datetime] = None
    model: str
    message_count: int = 0

class ChatRequest(BaseModel):
    user_id: str
    character_id: str
    session_id: Optional[str] = None  # None 则新建会话
    message: str

class RecallResult(BaseModel):
    source: Literal["long-term", "character-memory"]
    date: str
    content: str
    score: float
```

## 3. 记忆机制详细设计

### 3.1 记忆写入流程

#### 3.1.1 对话消息实时写入

```python
# services/memory_service.py
async def append_message(session_id: str, message: Message):
    """实时追加消息到 history.jsonl"""
    filepath = get_history_path(session_id)
    line = message.model_dump_json() + "\n"
    async with aiofiles.open(filepath, 'a', encoding='utf-8') as f:
        await f.write(line)
```

**不涉及 LLM，纯文件 I/O，延迟 < 5ms。**

#### 3.1.2 会话结束后的记忆蒸馏（异步）

```
触发条件：用户主动结束会话 / 会话闲置超过 30 分钟
执行方式：后台异步任务（不阻塞对话响应）
```

**蒸馏流程：**

```python
# services/distill_service.py
async def distill_session(session_id: str):
    # 1. 读取完整对话历史
    history = await read_history(session_id)
    
    # 2. 生成会话摘要
    summary = await llm.generate_summary(history)
    await save_summary(session_id, summary)
    
    # 3. 提取需要写入长期记忆的信息
    new_memories = await llm.extract_memories(summary)
    # new_memories 结构:
    # {
    #   "user_preferences": ["..."],   → 写入 long-term.md
    #   "character_relationship": ["..."]  → 写入 character/memory.md
    # }
    
    # 4. 去重后追加
    for item in new_memories.user_preferences:
        if not await is_duplicate(item, "long-term", user_id):
            await append_long_term(user_id, item)
    
    for item in new_memories.character_relationship:
        if not await is_duplicate(item, "character-memory", character_id):
            await append_character_memory(character_id, item)
```

**去重逻辑（M0 关键词重叠）：**

```python
async def is_duplicate(new_entry: str, memory_type: str, target_id: str) -> bool:
    recent_entries = await get_recent_entries(memory_type, target_id, limit=20)
    new_keywords = set(jieba.lcut(new_entry))
    
    for entry in recent_entries:
        entry_keywords = set(jieba.lcut(entry))
        overlap = len(new_keywords & entry_keywords) / len(new_keywords)
        if overlap > 0.6:  # 关键词重叠 > 60% 视为重复
            return True
    return False
```

### 3.2 记忆检索流程（recall 工具）

#### 3.2.1 检索触发

LLM 通过 function calling 调用 `recall` 工具：

```json
{
  "name": "recall",
  "arguments": {
    "query": "阿宁喜欢吃什么"
  }
}
```

**双通道触发优化（降低延迟）：**

```
用户输入
    │
    ▼
规则预判（< 1ms）：
    检测关键词："记得"、"上次"、"以前"、"我喜欢"、"我们约"、"还记得"
    │
    ├── 命中 → 直接执行检索，结果注入 Prompt（省掉一轮 LLM 决策）
    │
    └── 未命中 → 交给 LLM 决定是否调用 recall
```

#### 3.2.2 检索算法

```python
# services/memory_service.py
async def recall(user_id: str, character_id: str, query: str, top_k: int = 10) -> List[RecallResult]:
    keywords = [w for w in jieba.lcut(query) if len(w) > 1]
    if not keywords:
        return []
    
    files_to_search = [
        get_long_term_path(user_id),
        get_character_memory_path(character_id),
    ]
    
    results = []
    for filepath in files_to_search:
        sections = parse_markdown_by_date(filepath)  # 按 ## 日期分段
        source = "long-term" if "long-term" in filepath else "character-memory"
        
        for section in sections:
            date = section.date
            recency_weight = 1.0 / (1 + (date.today() - date).days)
            
            for entry in section.entries:
                score = sum(1 for kw in keywords if kw in entry.text)
                if score > 0:
                    results.append(RecallResult(
                        source=source,
                        date=str(date),
                        content=entry.text,
                        score=score * recency_weight
                    ))
    
    results.sort(key=lambda x: x.score, reverse=True)
    return results[:top_k]
```

**性能估算：**
- 文件读取：< 10ms（文件通常 < 50KB）
- 关键词匹配：< 5ms
- 总延迟：< 20ms（不包含 LLM 决策时间）

### 3.3 Prompt 组装

```python
# services/chat_service.py
async def build_prompt(user_id, character_id, session_id, user_message, recall_results=None):
    system_prompt = PROMPTS["system"]  # 基础指令 + recall 工具说明
    
    character_profile = await read_character_profile(character_id)
    user_profile = await read_user_profile(user_id)
    
    history = await get_recent_history(session_id, max_messages=20)
    history_messages = [{"role": m.role, "content": m.content} for m in history]
    
    messages = [
        {"role": "system", "content": system_prompt},
        {"role": "system", "content": f"【角色设定】\n{character_profile}"},
        {"role": "system", "content": f"【用户档案】\n{user_profile}"},
        *history_messages,
    ]
    
    if recall_results:
        recall_text = format_recall_results(recall_results)
        messages.append({"role": "system", "content": f"【回忆起的相关信息】\n{recall_text}"})
    
    messages.append({"role": "user", "content": user_message})
    return messages
```

**Token 预算控制：**

| 部分 | 预算 | 裁剪策略 |
|------|------|---------|
| System Prompt | 500 | 固定 |
| 角色设定 | 1000 | 不裁剪（核心） |
| 用户档案 | 300 | 不裁剪（本就精简） |
| 对话历史 | 3500 | 滑动窗口，从最旧开始裁 |
| recall 结果 | 800 | 只取 top-K，超预算截断 |
| 用户输入 | 500 | 不裁剪 |

### 4.1 对话接口

**请求：**
```json
{
  "user_id": "u_001",
  "character_id": "c_001",
  "session_id": "s_001",
```

**响应（SSE 流）：**
```
event: token
data: {"content": "嗯"}

event: token
data: {"content": "…"}

event: token
data: {"content": "怎么"}

...

event: done
data: {"session_id": "s_001", "message_id": "m_001"}
```

**流程：**
1. 接收消息 → 写入 history.jsonl
2. 规则预判是否需要 recall
3. 组装 Prompt → 调用 LLM（流式）
4. 逐 token 推送 SSE
5. 完整回复写入 history.jsonl
6. 返回 session_id 和 message_id

**请求：**

**响应：**

## 5. 延时优化详细设计

### 5.1 首字延迟优化（SSE 流式）

```python
# api/chat.py
@router.post("/send")
async def send_message(request: ChatRequest):
    async def event_generator():
        # 1. 写入用户消息（< 5ms）
        await memory_service.append_message(session_id, user_msg)
        
        # 2. 规则预判 recall（< 1ms）
        recall_results = None
        if should_recall(request.message):
            recall_results = await memory_service.recall(...)
        
        # 3. 组装 Prompt（< 10ms）
        messages = await chat_service.build_prompt(..., recall_results)
        
        # 4. 流式调用 LLM，逐 token 推送
        async for chunk in llm_adapter.stream_chat(messages):
            yield f"event: token\ndata: {json.dumps({'content': chunk})}\n\n"
        
        # 5. 写入 AI 回复（< 5ms）
        await memory_service.append_message(session_id, ai_msg)
        
        yield f"event: done\ndata: {json.dumps({'session_id': session_id})}\n\n"
    
    return StreamingResponse(event_generator(), media_type="text/event-stream")
```

**目标：首字延迟 < 800ms（取决于 LLM API）**

### 5.2 recall 调用延迟优化

| 策略 | 说明 | 节省时间 |
|------|------|---------|
| 规则预判 | 命中关键词直接检索，跳过 LLM 决策轮 | ~1s |
| 关键词检索 | 纯文本匹配，无 embedding 计算 | ~500ms |
| 并发检索 | 长期记忆和角色记忆并行读取 | ~5ms |
| 结果缓存 | 同一会话内相同 query 缓存 5 分钟 | ~20ms |

### 5.3 LLM 调用优化

- **HTTP 连接池**：使用 `httpx.AsyncClient` 复用连接
- **就近区域**：配置 LLM API 使用延迟最低的区域节点
- **超时控制**：首 token 超时 10s，整体超时 60s
- **降级策略**：主模型超时自动切换备用模型

### 5.4 记忆蒸馏不阻塞

```python
# 会话结束后立即返回，蒸馏在后台执行
@router.post("/end")
async def end_session(request: EndRequest):
    # 立即返回
    background_tasks.add_task(distill_service.distill_session, request.session_id)
    return {"status": "distilling"}
```

### 5.5 前端优化

- **流式渲染**：收到 token 立即追加到气泡，不等完整回复
- **输入预加载**：用户输入时禁用发送按钮防重复
- **消息分页**：历史消息分页加载，每次 20 条
- **左滑动画**：使用 Flutter `AnimatedContainer` 做 200ms 过渡

## 6. 错误处理与降级

| 场景 | 处理策略 |
|------|---------|
| LLM API 超时 | 重试 1 次，失败则切换备用模型 |
| recall 检索失败 | 忽略，按无记忆继续对话 |
| 记忆文件损坏 | 从 history.jsonl 重建摘要 |
| 网络断开 | 前端显示重连提示，消息本地缓存 |
| 文件写入失败 | 重试 3 次，失败记录日志 |

## 7. 安全设计

- **API Key 保护**：LLM API Key 仅存在后端 `.env`，不暴露给前端
- **用户隔离**：每个 user_id 独立目录，文件路径校验防止越权
- **输入过滤**：用户输入做基本长度限制（单条 < 2000 字）
- **记忆审计**：用户可查看和删除自己的记忆文件
