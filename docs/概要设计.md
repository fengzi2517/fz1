# AI 角色扮演聊天工具 - 概要设计文档

> 版本：v1.0 | 日期：2026-11-10 | 状态：待评审

## 1. 项目概述

### 1.1 产品定位
一款面向日常使用的手机端 AI 角色扮演聊天工具，支持自定义角色人设导入、多轮对话记忆、语音交互，参考"猫箱"软件的产品形态。

### 1.2 目标用户
- 希望与自定义 AI 角色进行沉浸式对话的用户
- 需要角色陪伴、情感倾诉、剧情互动的用户

### 1.3 核心价值
- **人设可控**：用户可导入/编辑角色设定，AI 严格遵循人设
- **记忆自然**：模拟人类记忆机制，对话有连续性但不被记忆淹没
- **体验流畅**：低延迟响应，支持语音输入输出

## 2. 里程碑规划

| 版本 | 核心功能 | 关键交付 |
|------|---------|---------|
| **M0** | 对话 + 记忆基础 + 界面设置 | 单人对话跑通，记忆机制闭环，左滑设置面板 |
| **M1** | ASR 语音识别 + TTS 语音合成 | 语音输入输出，记忆语义检索升级 |
| **M2** | 多角色管理 + 群聊 | 角色库管理，多角色群聊机制 |

## 3. 技术选型

| 层级 | 技术 | 说明 |
|------|------|------|
| 移动端 | Flutter (Dart) | 跨平台，一套代码出 Android + iOS，UI 表现力强 |
| 后端 | FastAPI (Python) | 异步框架，适合 I/O 密集型 LLM 调用 |
| LLM | OpenAI 兼容协议 | 支持 OpenAI / DeepSeek / GLM / Kimi 等多家切换 |
| 记忆存储 | Markdown 文件 + JSON/JSONL | 人可读、可编辑、无额外数据库依赖（M0） |
| 通信协议 | HTTP + SSE 流式 | 对话流式输出，降低首字延迟 |
| 分词 | jieba | 中文关键词检索 |

### 4.2 模块职责

| 模块 | 职责 |
|------|------|
| **ChatService** | 编排 LLM 对话：组装 Prompt、调用 LLM API、处理流式输出、管理工具调用（recall） |
| **MemoryService** | 记忆读写：profile 读写、长期记忆追加、会话摘要生成、按需检索 |
| **CharacterService** | 角色人设管理：导入解析、CRUD、人设格式化 |
| **LLMAdapter** | LLM API 封装：统一 OpenAI 兼容接口，支持多供应商切换 |

## 5. 记忆机制概要

### 5.1 设计原则
- **纯 Markdown 存储**：记忆、人设均为 md 文件，人可读可编辑
- **追加式写入**：长期记忆只追加不覆盖，保留完整时间线
- **按需检索**：默认不注入长期记忆，LLM 通过 recall 工具自主决定是否翻阅
- **蒸馏写入**：会话结束后由 LLM 从对话中提取值得记住的信息，写入长期记忆

### 5.2 记忆分层

| 层级 | 存储 | 注入策略 |
|------|------|---------|
| 角色人设 | `characters/{id}/profile.md` | 每次对话注入 |
| 用户档案 | `users/{id}/profile.md` | 每次对话注入（体量小） |
| 短期记忆 | `sessions/{id}/history.jsonl` | 滑动窗口注入最近 N 条 |
| 角色记忆 | `characters/{id}/memory.md` | 按需检索（recall 工具） |
| 长期记忆 | `users/{id}/long-term.md` | 按需检索（recall 工具） |
| 会话摘要 | `sessions/{id}/summary.md` | 不直接注入，作为蒸馏素材 |

### 5.3 recall 检索
- 纯文本关键词匹配（jieba 分词），无向量库
- 按日期近度加权，返回 top-K
- 无匹配返回空（模拟"想不起来"）

## 6. 前端界面概要

### 6.1 页面结构
```
┌─────────────────────┐
│   顶部栏（角色名）    │
├─────────────────────┤
│                     │
│   消息列表区域       │
│   （气泡式对话）     │
│                     │
├─────────────────────┤
│  输入框 + 发送按钮   │
│  （M1: 语音按钮）    │
└─────────────────────┘

左滑 → 设置面板：
┌─────────────────────┐
│ 模型选择            │
│ Temperature 滑块    │
│ 记忆设置            │
│ 角色切换            │
│ 清空对话            │
└─────────────────────┘
```

### 6.2 核心交互
- **对话**：输入文字发送，SSE 流式接收回复
- **左滑**：唤出设置面板
- **角色导入**：支持粘贴文本 / 导入 md/txt/json 文件
- **M1 语音**：长按语音按钮录音，ASR 转文字发送；回复可点击播放 TTS

## 7. 延时优化策略（概要）

| 优化点 | 策略 | 预期效果 |
|--------|------|---------|
| 首字延迟 | SSE 流式输出，逐 token 推送 | 用户感知延迟 < 1s |
| recall 调用 | 规则预判 + LLM 决策双通道 | 减少不必要的工具调用轮次 |
| LLM 连接 | HTTP 连接池复用 + 就近区域 | 降低网络握手开销 |
| 记忆蒸馏 | 会话结束后异步执行，不阻塞对话 | 对话流程零额外延迟 |
| 历史加载 | 分页加载，懒渲染 | 长对话不卡顿 |

## 8. M1/M2 扩展预留

| 扩展点 | M0 预留方式 |
|--------|------------|
| 向量语义检索 | recall 函数内部可替换实现，接口不变 |
| ASR/TTS | 预留 `/voice/asr` 和 `/voice/tts` 接口路径 |
| 多角色管理 | 角色已独立目录存储，支持 CRUD |
| 群聊 | 会话目录可扩展为 group_sessions，角色记忆独立维护 |
