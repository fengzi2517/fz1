## 2. P0 地基

### 2.1 存储引擎：文件 → SQLite（WAL）

- 新增 `backend/app/db.py`：标准库 `sqlite3`，单连接 + `threading.RLock` + `check_same_thread=False`，`PRAGMA journal_mode=WAL / foreign_keys=ON`，`row_factory=Row`；`transaction()` 上下文用 `BEGIN IMMEDIATE` 保证多写原子性。
- 新增 `backend/app/store.py`（488 行，全部 SQL 唯一出口）：
  - 11 张表：`users / characters / sessions / messages / memory_entries / memory_log / recall_ledger / groups / relations / distill_jobs / user_profile`
  - `messages.seq` 会话内单调递增（`UNIQUE(session_id, seq)`），`get_messages(offset_after/limit)` 取窗口、`count_messages` 计数、`first_message_time` 判跨日；swipe 多候选是 `messages.candidates` + `active_candidate` 列（`set_candidates`），半截回复是 `messages.flags` JSON 里的 `interrupted`（`mark_flag`，G8 的真相源）。
  - 租户隔离在每个查询都以 `user_id` 为条件（列表/单条/删除一律带 `WHERE user_id=?`）。
  - `distill_jobs` 任务队列：`enqueue_job` 只对 `status IN ('pending','running')` 的同 `(session_id,kind,range_start,range_end)` 去重（所以 `failed` 不挡重入）、`claim_job` 取队首 `pending` 并 `attempts+1`、`finish_job` 落 `done`/`failed`+`last_error`、`reset_running_jobs()` 在 worker 启动时把上次进程遗留的 `running` 孤儿放回 `pending`（无运行中超时回收，靠重启复位）。
- 修复 01 文档 §6.1（全文件重写竞态）与 §6.8（有损往返）：`characters.card_json` 永久保留 `raw_content` 原文 + `parsed` 解析结果，`profile_md` 降级为纯注入视图；编辑时以原文为准，不再二次解析已渲染文本。

### 2.2 鉴权与路径校验

- `backend/app/core/security.py`：
  - `hash_password/verify_password`（PBKDF2-HMAC-SHA256，100k 迭代，随机盐，`hmac.compare_digest`）。
  - `create_token/decode_token`：stdlib HS256 JWT（`header.payload.signature`），`exp` 校验 + 签名 `compare_digest`；密钥来自 `AUTH_SECRET`，未配置则以 `O_CREAT|O_EXCL, 0o600` 生成到 `DATA_DIR/auth_secret.key`，读到历史遗留文件时顺手 `chmod 0600`（`write_text()` 会沿用进程 umask，见 §5 缺陷 7）。
  - `ID_RE = ^[A-Za-z0-9_\-]{1,64}$` + `validate_id()`：所有 `user_id / character_id / session_id / group_id / message_id` 入口校验，阻断 §6.4 路径穿越。
  - `current_user` 依赖：`AUTH_ENABLED=true` 接受 `Authorization: Bearer` **或** `?token=`（原生播放器无法设 header）；`=false` 走开发模式 `?user_id=`。
- `backend/app/api/auth.py`（新增）：`POST /api/auth/register`（用户名 ≥2，重复 409）、`POST /api/auth/login` → `{user_id, token, username}`。
- 全部业务路由挂 `UserDep`；`/health`、`tts|asr /status` 保持公开（前端探测用）。

### 2.3 LLM Gateway 修复与生命周期

- `llm_adapter` 统一 `chat / chat_json / chat_stream / embed`：超时+`LLM_FALLBACK_MODEL` 重试（§6.5），`chat_json` 走 `extract_json` 容错（代码块/前后杂质）。
- `main.py` 改 `asynccontextmanager` lifespan：建目录 → `get_db()` 懒初始化 → `logging.basicConfig` → 启动蒸馏 worker 与 `IdleSweeper`；shutdown 停 worker/巡检并 `close()` 连接（§6.7 无生命周期）。
- 补修：`chat()` 等非流式调用此前仍下发 `stream: true`，OpenAI 兼容端点会回 SSE 文本导致 `resp.json()` 解析失败（摘要/蒸馏/画像/冲突消解全链路不可用）；`_payload` 现按调用意图区分 `stream`，由 `test_llm_gateway.py` 抓出。
- SSE 统一 `app/api/sse.py` 的 `sse_response()`（`data: {json}\n\n` + `Cache-Control: no-cache` + `X-Accel-Buffering: no`），替代各 API 内复制粘贴。

### 2.4 旧数据迁移

- `backend/app/migrate_files.py`（新增，一次性）：`users/{uid}/profile.md|long-term.md`、`characters/{cid}/profile.md|memory.md|sessions/{sid}/history.jsonl`、`groups/{gid}/meta.json|history.jsonl|summary.md` → SQLite。
- 保留原始 ID（可回填）、`distilled_upto`/`summary` 一并迁移；不符合 `ID_RE` 的目录跳过并记入 `stats["skipped"]`；迁移用户生成 `migrated_{uid}` 账号并打印随机密码。
- 实测旧样例树：`{"users":1,"characters":1,"sessions":1,"messages":4,"memories":3,"groups":1,"skipped":[]}`，二次运行幂等（测试 `test_migrate.py` 覆盖）。

## 3. P1 记忆引擎

### 3.1 上下文装配（修复"跨会话失忆"）

`app/services/chat_service.py` 的 `assemble_context()` 按 token 预算装配（`CTX_WINDOW_TOKENS` 默认 32000，profile 0.25 / summary 0.15 / recall 0.15 / history ≥0.40）：

- **摘要回注**（01 文档 §3.2 断点 2）：`sessions.summary` 首次进入 prompt，单聊/群聊一致。
- **画像回注**（§3.2 断点 1）：`write_user_profile` 现在有调用方并真正写库（`RELATION/PROFILE_UPDATE`）。
- 预算不足时先压 recall/summary，`truncate_at_sentence` 按句末标点从尾部保留并加 `…` 前缀；当前用户消息永远最后。
- 轮换判定 `rotate_reason`：消息数超阈 / 跨日 / token 超限，触发即归档旧会话并继承 summary。

### 3.2 混合检索（§3.2 断点 3、D6）

`memory_service.recall()` 每轮调用，不再靠 16 个触发词：

```
score = 1.0·min(BM25,10)/10 + 2.0·max(cosine,0) + 0.5·day_decay(30d 半衰期)
score ×= (0.6 + 0.8·importance)
score ×= 0.3  若近 LEDGER_PENALTY_ROUNDS(3) 轮已注入（召回账本防复读，G5）
```

- 分词 `tokenize()` 用 jieba（长度 >1 词），BM25 k1=1.5/b=0.75，语料统计在候选集上一次性预计算。
- 向量：`llm_adapter.embed_available` 时启用；`EMBED_*` 未配置则退化为 BM25+时间+重要性，逻辑不变。
- 弱向量单独命中（`< RECALL_VEC_THRESHOLD` 且 BM25=0）丢弃；零命中走 `_recent_fallback`（按 重要性×衰减 注入最近高价值记忆，避免"我不记得"体验灾难）。

### 3.3 mem0 式冲突消解（§3.1 / D3 / G4）

`add_memory_resolved()`：`_find_similar`（词面重叠 top5）→ `RESOLVE_MEMORY_PROMPT` → `ADD/UPDATE/DELETE/NOOP/MERGE`：

- `UPDATE`/`MERGE` 改写主条目并 `superseded` 其余；`DELETE` 标记旧条目 + 新增，写 `DELETE+ADD` 日志；非法动作/LLM 不可用 → 词面重合 >`RECALL_KEYWORD_OVERLAP_THRESHOLD` 判 NOOP，否则 ADD。
- `target_ids` 只接受相似集内真实 ID → 防 LLM 幻觉改他条（测试覆盖）。
- 全量审计：`memory_log`（ADD/UPDATE/MERGE/DELETE/ARCHIVE + detail），`GET /api/memory/log` 可查。

### 3.4 遗忘与导出（G6）

- `ACTIVE_ENTRY_LIMIT=800`：超限按 `importance×day_decay` 归档最低分为 `archived`（不物理删，可恢复）并写 ARCHIVE 日志。
- `export_markdown()`：`profile` / `long_term` / `characters/{cid}` 三段 md 导出，保留"记忆可审计可读"卖点。

### 3.5 事务化蒸馏（§3.1 / D1 / G8）

`distill_service`：`request()` 按 `distilled_upto` 判阈值入队 → worker `claim_job` → `_plan_*` 产计划（纯计算，不落库）→ `_apply` 在**单个 `BEGIN IMMEDIATE` 事务**里写 summary + `distilled_upto` + 记忆 + 画像 + 关系。

- LLM 失败/空摘要 → 抛异常，`finish_job(ok=False)`，状态零污染；`enqueue_job` 的去重只看 `pending/running`，故 `failed` 不挡重入——下一次对话触发或 `IdleSweeper` 巡检都会按未推进的游标重新入队同区间（`test_distill_worker.py` 断言"失败无部分写入 + 二次入队跑通 + 巡检兜底重试"）。
- 幂等：同区间二次 `request()` 返回 0；prompt 带"（第 N 条为止）"里程碑标记。
- **G8**：`interrupted` 的半截回复永不进入后续 transcript（`transcript` 过滤 + 移除旧版"不足 2 条就取前 2 条"兜底——该兜底会把打断内容复活）。

## 4. P2 群聊调度

`app/services/group_service.py` 的 `GroupScheduler`（重写，含 `pick()` 纯函数便于测试）+ `chat_stream` 改造，对应 02 文档借鉴项"ST Natural Order"：

1. **@提及优先**：整词匹配 `name`/`nickname`（避免"@小美"命中"@小美玲"），命中即只让被点名的成员发言（含静音者，显式优先）。
2. **target 模式**：只回复指定成员，忽略全局轮转。
3. **all/auto 模式**：`rng.choices` 按 `talkativeness` 加权，近轮发言人 ×0.4 降权；`ta=0` 有 `rng.random() > ta/100*1.4` 静默概率；全局轮换起点用 `group_total_user_turns`（**在写入本轮用户消息之前**计算，修 G2 的窗口抖动/起点漂移）。
4. **并行扇出**：`GROUP_PARALLEL_REPLY=true` 时多成员 `asyncio.gather` + `Queue` 复用单条 SSE，事件携带 `character_id`；插话（HTTP/WS）→ `asyncio.Event` + `shield` 停止，半截回复 `interrupted=True` 落库。
5. **群记忆**：群内成员记忆加"（群聊见闻）"前缀写入 `scope=group`，`group_service` 装配公告、好感度关系行；成员上限 `GROUP_MEMBER_LIMIT=6`、每轮 `GROUP_SPEAKERS_PER_ROUND=2`。

**测试过程中定位并修复的真实产品缺陷**（非测试问题）：

1. `distill_service._char_name` 未实现 → 群聊蒸馏 AttributeError（单聊被 try/except 吞掉，静默丢关系更新）。
2. G8：不足 2 条时 `messages[:2]` 兜底把被打断的半截回复重新喂给 LLM。
3. G2：`group_total_user_turns` 在写入本轮用户消息之后计算，首轮轮换起点偏移 1。
4. `store.recent_recalled` 忽略 `within_rounds` 参数，防复读窗口实际失效。
5. `resolve_session` 继承 summary 后返回的是旧 dict，调用方看不到已生效的摘要。
6. `llm_adapter.chat()` 非流式调用仍下发 `stream: true`，OpenAI 兼容端点会返回 SSE 文本，`resp.json()` 直接解析失败——即摘要/蒸馏/画像/冲突消解等所有走 `chat()` 的 P1 链路在真实 API 上全线不可用。已按调用意图区分 `stream` 参数。
7. **`auth_secret.key` 权限过松**（真机冒烟抓到的唯一安全级缺陷）：`config.py` 用 `Path.write_text()` 落 JWT 签名密钥，权限取进程 umask——本机 umask `0002` 直接产出 **0664**，同组用户可读密钥并伪造任意用户的 token。改为 `os.open(..., O_WRONLY|O_CREAT|O_EXCL, 0o600)` 创建，并对已存在的宽权限文件 `chmod 0o600` 收紧；`test_security.py::TestAuthSecretFile` 三条回归（新生成 0600 / 旧 0644 被收紧且复用旧值 / 重启密钥不变）。

## 6. 已知限制与后续（P3/P4）

- **前端未接登录**：`AUTH_ENABLED` 默认 `true`（安全默认），Flutter 尚未带 token，本地开发需先设 `AUTH_ENABLED=false` 走 `?user_id=` 模式；P3 接入登录页后即可翻回。`/api/auth/register|login` 与 `users`（`pw_hash`）表已就绪。
- 群聊 WS 的 `token` 参数已按 `AUTH_ENABLED` 校验（4401/4404），但前端尚未传。
- 语音（TTS GET query/无流式单音色）、多模态、记忆"重要性"自动学习、评测集（LLM-as-judge）仍在 03 方案的 P3/P4。
- `data/`、`.venv/`、`auth_secret.key`、`.env` 必须保持 gitignore，不进仓库。
